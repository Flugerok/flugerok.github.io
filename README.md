# Деревянные флюгеры — интернет-магазин на GitHub Pages

Полностью статический сайт (HTML + CSS + JavaScript, без backend, PHP и баз
данных), готовый к размещению на GitHub Pages.

---

## 1. Как разместить сайт на GitHub Pages

1. Создайте новый репозиторий на GitHub, например `flugery-site`
   (Settings → New repository). Можно сделать его публичным.
2. Загрузите в репозиторий **все файлы и папки** из этого проекта, сохранив
   структуру (см. раздел «Структура папок» ниже). Проще всего перетащить
   папку в веб-интерфейс GitHub (`Add file → Upload files`) либо
   запушить через git:
   ```
   git init
   git add .
   git commit -m "Первая версия сайта"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/flugery-site.git
   git push -u origin main
   ```
3. Включите GitHub Pages: в репозитории откройте
   `Settings → Pages → Build and deployment`, в поле **Source** выберите
   `Deploy from a branch`, ветку `main` и папку `/ (root)`. Сохраните.
4. Через 1–2 минуты сайт будет доступен по адресу вида:
   `https://ВАШ_ЛОГИН.github.io/flugery-site/`
5. Все ссылки в проекте относительные (без `/` в начале), поэтому сайт
   корректно работает как в корне домена, так и в подпапке репозитория —
   ничего дополнительно настраивать не нужно.

## 3. Где менять контакты

Все контакты хранятся в **одном файле**: `js/config.js`.

Откройте его и измените нужные строки:

```js
phone: "+375 (29) 000-00-00",       // где менять телефон
phoneLink: "tel:+375290000000",
telegram: "https://t.me/your_telegram", // где менять Telegram
telegramName: "@your_telegram",
email: "info@example.com",              // где менять email
```

После сохранения файла новые контакты автоматически появятся в шапке,
подвале, на странице «Контакты» и в модальном окне заказа на всех страницах.

## 4. Где менять название сайта

Тоже в `js/config.js`, поле:

```js
siteName: "Деревянные флюгеры",
```

## 5. Как добавить новый товар

Все товары описаны в файле `js/products.js` в виде списка объектов.

1. Скопируйте один из существующих товаров целиком (от `{` до `}`).
2. Вставьте копию перед закрывающей квадратной скобкой `]` в конце файла.
3. Измените поля:
   - `id` — латиницей, без пробелов, уникальный (например `sobaka`);
   - `name`, `shortName` — название товара;
   - `price` — цена числом (BYN, см. раздел 7);
   - `added` — дата добавления товара в каталог в формате `ГГГГ-ММ-ДД`
     (например `"2026-09-01"`): по ней работает сортировка «по дате
     добавления», она же показывается на странице товара;
   - `category`, `size` — сейчас в фильтрах каталога не используются
     (фильтры «Большие/Маленькие/Вертушки» убраны), можно не заполнять;
   - `popular` — `true`, если товар должен попадать в блок «Популярные»
     на главной и под фильтр «Популярные» в каталоге;
   - `shortDescription`, `description` — тексты для карточки и страницы;
   - `images` — пути к фотографиям (см. раздел 7);
   - `youtube` — см. раздел 9;
   - `characteristics` — объект «характеристика: значение».

После сохранения файла товар сразу появится в каталоге и будет доступен
по адресу `product.html?id=ваш-id` — этого достаточно, чтобы всё
заработало. Чтобы у товара появилась ещё и своя "чистая" страница вида
`products/ваш-id.html` с готовыми мета-тегами для поисковиков и
Telegram — прочитайте раздел 6 и запустите `build-products.js`.

## 6. Отдельная страница для каждого товара и индексация (SEO)

Вы задавались вопросом, не стоит ли сделать для каждого товара свою
HTML-страницу вместо одного общего `product.html?id=...` — и это
хорошая мысль, так и сделано.

**Как это устроено.** Единственное место, где вы редактируете товары —
по-прежнему `js/products.js` (раздел 5). Отдельный скрипт
`build-products.js` читает оттуда данные и генерирует готовые файлы
`products/petuh.html`, `products/loshad.html` и т.д. — по одному на
каждый товар, с уже готовыми (не через JavaScript) `<title>`,
description, Open Graph-картинкой и Schema.org-разметкой. Это даёт две
вещи:

1. **Красивый адрес** — `products/petuh.html` вместо
   `product.html?id=petuh`.
2. **Корректные превью ссылок.** Когда вы отправите ссылку на товар в
   Telegram, WhatsApp или VK, эти мессенджеры не выполняют
   JavaScript — они читают только "сырой" HTML страницы. Раньше в нём
   был один и тот же шаблонный текст для всех товаров; теперь для
   каждого товара в файле сразу лежит его собственное название,
   описание и фото — превью будет показывать именно тот товар, на
   который вы дали ссылку.

**Как запускать.** После того как вы добавили, изменили или удалили
товар в `js/products.js` (раздел 5) — запустите из папки сайта:

```
node build-products.js
```

(нужен установленный Node.js, https://nodejs.org — ставится один раз).
Скрипт перезапишет файлы в папке `products/`. Их, как и любые другие
изменённые файлы, нужно закоммитить и запушить в GitHub.

Файлы внутри `products/` руками лучше не редактировать — при
следующем запуске скрипта они полностью перезапишутся. Все правки
вносите в `js/products.js`.

**Если забыли запустить скрипт.** Ничего страшного — старый
универсальный `product.html?id=ваш-id` продолжает работать как
подстраховка для любого товара, даже совсем нового, для которого вы
ещё не генерировали отдельную страницу. Просто у такой ссылки не
будет заранее подготовленных мета-тегов, только сама страница товара.

**Карта сайта.** В комплекте есть `sitemap.xml` и `robots.txt` — они
помогают поисковикам быстрее найти и проиндексировать все страницы,
включая товары. В обоих файлах уже подставлен адрес
`flugerok.github.io` — если сайт будет жить по другому адресу
(например по собственному домену), замените его в `sitemap.xml` и
`robots.txt`. Если вы позже добавите
новый товар и перегенерируете `products/`, не забудьте дописать его
адрес отдельной строкой в `sitemap.xml` — либо просто попросите меня
это сделать.

## 8. Как добавить фотографии

1. Создайте папку для товара внутри `images/products/`, например:
   `images/products/sobaka/`
2. Положите туда фотографии — **рекомендуем 4–5 штук** на товар
   (квадратный формат, например 1000×1000 px, в JPG или WebP).
3. В `js/products.js` в поле `images` укажите пути к этим файлам:
   ```js
   images: [
     "images/products/sobaka/1.jpg",
     "images/products/sobaka/2.jpg",
     "images/products/sobaka/3.jpg",
     "images/products/sobaka/4.jpg",
     "images/products/sobaka/5.jpg",
   ],
   ```
4. Можно указать от одной фотографии до сколько угодно — все они появятся
   в галерее на странице товара: большая фотография сверху, под ней —
   миниатюры. При клике по миниатюре открывается соответствующее фото,
   а стрелками и свайпом на телефоне можно листать все фото по кругу.
   Если у товара указан YouTube-ролик (см. раздел 9), он добавляется
   в конец той же ленты миниатюр — так что видео и фото листаются вместе.

**Главное изображение (hero) на главной странице.** Сейчас это лёгкая
векторная (SVG) иллюстрация `images/hero/hero-wide.svg`, специально
нарисованная широкоформатной, во весь экран — так сайт выглядит
эффектно, но при этом грузится быстро (в отличие от тяжёлых JPG-фото
на весь экран). Если захотите заменить её на свою настоящую фотографию:
1. Подготовьте фото в широком формате (например 1920×1080), сохраните
   как оптимизированный `.webp` или `.jpg` — так, чтобы файл весил
   не больше 250–400 КБ (иначе первый экран сайта будет грузиться долго).
2. Положите файл в `images/hero/`, например `images/hero/hero-photo.webp`.
3. В `index.html` найдите тег `<img class="hero__bg" ...>` и замените
   `src="images/hero/hero-wide.svg"` на путь к своему файлу.
   Тёмный градиент поверх фото (`hero__scrim`) подстроится сам — он
   нужен, чтобы текст на фото оставался читаемым.

**Логотип.** Сейчас это `images/logo/logo.webp` — широкий логотип
с названием (бывшая надпись «Деревянные флюгеры» рядом с картинкой
убрана: название теперь часть самого изображения логотипа). Чтобы
заменить на свою версию:
1. Сохраните новый логотип в `images/logo/` (желательно с прозрачным
   фоном — PNG или WebP с альфа-каналом, чтобы он одинаково хорошо
   смотрелся и на светлой шапке, и на тёмном футере).
2. Замените файл `images/logo/logo.webp` на свой (можно оставить то
   же имя файла — тогда вообще ничего больше менять не придётся).
3. Если у нового логотипа сильно другие пропорции (не вытянутый
   широкий, а, скажем, квадратный) — высоту задают правила
   `.brand img` и `.footer-brand img` в `css/style.css`, можно
   подправить там.
4. На тёмном футере под логотипом сейчас светлая подложка (на случай
   тёмного логотипа) — если ваш новый логотип светлый и сам по себе
   хорошо виден на тёмном фоне, подложку можно убрать, удалив в
   `css/style.css` в правиле `.footer-brand img` строки `background`
   и `padding`.

Если меняете только файл с тем же именем `logo.webp` — всё остальное
(в том числе страницы `products/*.html` и `SN/*/*.html`) подхватит
новый логотип само, без перегенерации.

## 9. Как вставить YouTube ID

В `js/products.js` у товара есть поле:

```js
youtube: "",
```

1. Откройте нужное видео на YouTube.
2. Скопируйте ID из адресной строки — это часть после `v=`.
   Например, в ссылке `https://www.youtube.com/watch?v=AbCdEfGhIjK`
   идентификатор — `AbCdEfGhIjK`.
3. Вставьте его в поле:
   ```js
   youtube: "AbCdEfGhIjK",
   ```

Видео не выводится отдельным блоком — оно становится последней
миниатюрой в галерее товара (с иконкой ▶ поверх превью). При клике на
неё видео проигрывается прямо в основной области галереи, на месте
большого фото. Если поле оставить пустым (`""`), эта миниатюра просто
не появится — ничего дополнительно скрывать не нужно.

> Для примера у товаров «Петух» и «Лошадь» уже подставлены реальные
> демонстрационные ролики о флюгерах — чтобы сразу было видно, как это
> выглядит и работает. Замените `youtube` на ID своих видео (или на
> `""`, если видео пока нет) — у остальных товаров это поле изначально
> пустое.

## 11. Подключение формы заказа (Formspree)

Сайт статический, поэтому форма заказа не может сама отправлять письма —
нужен внешний сервис-приёмник форм.

1. Зарегистрируйтесь на [formspree.io](https://formspree.io) (или на
   похожем сервисе: Getform, Basin, Web3Forms).
2. Создайте новую форму и скопируйте её адрес (endpoint), например:
   `https://formspree.io/f/xxxxabcd`
3. Откройте `js/config.js` и вставьте адрес в поле:
   ```js
   orderFormEndpoint: "https://formspree.io/f/xxxxabcd",
   ```

Пока это поле пустое, форма не пытается отправить данные "в никуда" —
вместо этого посетителю показываются телефон и Telegram для связи напрямую.

## 12. Блок с цифрами («~20 флюгеров...») на главной

Сразу под первым экраном есть тёмная полоса с четырьмя цифрами
(«~20 флюгеров изготовлено», «2 года занимаемся этим ремеслом»,
«20–30 дней в среднем на изготовление» и число моделей в каталоге).
Это обычный текст без анимации — значения вы вписываете сами и
обновляете по мере роста. Исключение — «моделей в каталоге»: это число
считается автоматически по количеству товаров в `js/products.js`.

Меняются они прямо в `index.html`, в секции с классом `stats`:

```html
<div class="stats__item">
  <div class="stats__number">~20</div>
  <div class="stats__label">флюгеров изготовлено вручную</div>
</div>
```

Отредактируйте текст внутри `stats__number` (сама цифра) и
`stats__label` (подпись под ней) — можно добавить, убрать или
переставить местами карточки, просто скопировав/удалив такой блок.

## 13. Разное

- Цветовая палитра, шрифты и все стили — в `css/style.css` и
  `css/responsive.css`.
- Блок FAQ на главной странице редактируется прямо в `index.html`
  (секция с классом `faq-list`) — можно добавлять новые вопросы, копируя
  один блок `.faq-item`.
- Каталог: фильтр «Все / Популярные» и сортировка по дате добавления
  (новые/старые сначала) и по цене работают полностью на JavaScript
  (`js/catalog.js`) без перезагрузки страницы. Даты берутся из поля
  `added` в `js/products.js` — в комплекте там стоят ПРИМЕРНЫЕ даты,
  замените их настоящими.

Если что-то не заработало после загрузки на GitHub Pages — чаще всего
причина в том, что не все папки/файлы были загружены с сохранением
структуры. Сверьтесь со схемой в разделе 2.

## 14. Паспорт изделия — уникальный номер на каждом флюгере

Отдельная от каталога функция: у каждого физического флюгера может
быть свой десятизначный номер (например `SNG01A0926`), который вы
наносите на само изделие. Через любое время владелец вбивает этот
номер в Google или Яндекс и попадает на отдельную страницу именно
своего экземпляра — с датой изготовления (и тем, сколько дней прошло
с этой даты — считается автоматически при каждом открытии страницы) и
фотографиями на момент создания, которые открываются в модальном окне
на этой же странице с перелистыванием стрелками, клавишами ← → и
свайпом на телефоне.

**Это не то же самое, что каталог товаров.** `js/products.js` — это
модели, которые можно купить. `data/passports.js` — это история уже
изготовленных конкретных экземпляров.

**Как разложены файлы.** Страницы группируются по подпапкам —
отдельная подпапка на каждую модель, по первым трём буквам номера.
Например, номер `SNG01A0926` попадёт в файл `SN/SNG/SNG01A0926.html`,
а номера с другим трёхбуквенным началом (скажем, `CDX...`) окажутся в
своей подпапке `SN/CDX/`. Код модели скрипт определяет сам, из самого
номера — отдельно нигде вписывать его не нужно, достаточно, чтобы у
всех экземпляров одной модели номера начинались одинаково.

**Не ухудшает ли вложенность папок находимость в поиске?** Нет.
Поисковики находят такую страницу по совпадению текста (номер в
заголовке, в `<title>`, в тексте страницы), а не по тому, на каком
уровне вложенности лежит файл — двухуровневая папка `SN/SNG/...`
работает для этого ровно так же, как плоская `passport/...`. Разложить
по подпапкам можно свободно, для собственного удобства, это никак не
скажется на том, найдёт ли Google/Яндекс страницу по точному номеру.

**Как добавить новый паспорт:**

1. Откройте `data/passports.js` и скопируйте один из объектов в
   массиве `PASSPORTS`.
2. Заполните `number` (сам номер), `date` — дата изготовления **в
   формате `ГГГГ-ММ-ДД`**, например `"2026-09-01"` (это 1 сентября
   2026). Писать дату словами не нужно — скрипт сам превратит её в
   красивую русскую фразу на странице и по ней же браузер посетителя
   посчитает, сколько дней прошло. Также заполните опционально
   `modelId` (id модели из `js/products.js` — тогда на странице
   появится ссылка «Такая же модель есть в каталоге») и `photos`
   (фото этого экземпляра на момент изготовления).
3. Положите фотографии в `images/passports/ВАШ_НОМЕР/`.
4. Запустите из папки сайта:
   ```
   node build-passports.js
   ```
   (нужен Node.js — так же, как для `build-products.js` из раздела 6).
5. Скрипт создаст файл `SN/КОД_МОДЕЛИ/ВАШ_НОМЕР.html`. Закоммитьте и
   запушьте его вместе с остальными файлами.

**Важный отдельный шаг — вручную запросите индексацию** новой
страницы:
- **Google Search Console** → «Проверка URL» → вставить адрес
  страницы → «Запросить индексирование»;
- **Яндекс.Вебмастер** → «Индексирование» → «Переобход страниц» →
  вставить адрес.

Это нужно, потому что страницы паспортов **специально не добавлены**
ни в меню, ни в каталог, ни в `sitemap.xml` — на них нет ни одной
ссылки с сайта. Так и задумано: страницу может найти только тот, кто
уже знает точный номер. Но из-за этого поисковики сами, без вашей
подсказки, могут очень долго её не находить — ручной запрос
индексации решает это, никак не раскрывая остальные номера
посторонним.

**О приватности.** На страницах паспортов не должно быть имени,
телефона или адреса покупателя — эти страницы остаются в открытом
доступе и индексируются бессрочно. Только информация об изделии:
номер, дата, фото.

**Предупреждение о неоднозначных символах.** Скрипт `build-passports.js`
сам предупредит в консоли, если номер содержит легко путающиеся при
вводе символы (буква `O` и цифра `0`, буква `I`/`l` и цифра `1`) — это
не ошибка, генерация всё равно пройдёт, просто подсказка, чтобы
владельцу было проще ввести номер без опечатки.

> Также стоит знать: если репозиторий на GitHub публичный (обычный
> бесплатный вариант), технически подкованный человек может зайти
> прямо на страницу репозитория на github.com и увидеть список файлов
> в папке `SN/` — то есть все выданные номера разом. Сам же сайт
> (через обычный браузер) списком файлов не делится — так что для
> подавляющего большинства случаев это не проблема, но если хочется
> закрыть и эту лазейку, единственный способ — сделать репозиторий
> приватным, для чего нужен платный тариф GitHub (Pro и выше).

## 15. Информер погоды и ветра на главной странице

Небольшой полупрозрачный блок с температурой и ветром прямо в первом
экране главной страницы — тематически в духе флюгера. Работает без
backend: обращается напрямую из браузера посетителя к двум бесплатным
сервисам, которым не нужен API-ключ (ключ негде было бы спрятать на
статическом сайте, поэтому оба выбраны намеренно):

- **[Open-Meteo](https://open-meteo.com)** — сама погода и ветер;
- **BigDataCloud** (`reverse-geocode-client`) — определение названия
  города по координатам, используется только при нажатии «Мой город».

**Где менять город по умолчанию.** У метеослужб нет единого числа
«средняя погода по всей Беларуси» — поэтому по умолчанию показывается
конкретный город (Минск, как столица), а не выдуманное среднее. Чтобы
показывать другой город — откройте `js/config.js` и поменяйте:

```js
weatherCity: "Минск",
weatherLat: 53.9006,
weatherLon: 27.5590,
```

Координаты своего города можно посмотреть, например, на
google.com/maps — кликнуть по нужной точке, координаты появятся во
всплывающей подсказке.

**Кнопка «Мой город».** Маленькая круглая кнопка рядом с показаниями
запрашивает у браузера посетителя разрешение на геолокацию — **только
по клику**, сама по себе она ничего не запрашивает. Браузер покажет
свой стандартный системный запрос разрешения. Если посетитель
разрешит — показания переключатся на его фактическое местоположение;
если откажет или закроет запрос — просто ничего не изменится, никаких
ошибок на экране.

**Если что-то не загрузилось** (нет сети, сервис погоды недоступен и
т.п.) — информер просто не появляется на странице, без сломанного
вида и текста ошибок.

**Значок-вентилятор.** Маленькая иконка слева от показаний — это не
просто украшение: она крутится непрерывно, и скорость вращения
зависит от реальной скорости ветра по данным Open-Meteo — слабый
ветер крутит её медленно, сильный — заметно быстрее (от 7 секунд на
оборот в штиль до меньше секунды в сильный ветер). Направление ветра
("СЗ" и т.п.) показывается рядом текстом. Для посетителей с настройкой
«уменьшить движение» в операционной системе вращение отключается
само — вентилятор остаётся неподвижным, без анимации. Диапазон
скорости вращения настраивается в `js/weather.js`, в функции
`spinDurationFromWind`.

Блок подключён только на главной странице (`index.html`), в файле
`js/weather.js`. Стили — в `css/style.css`, класс `.weather-chip`.

## 16. Блок «Новости орнитологии» на главной странице

Три карточки с новостями о наблюдении за птицами и миграционных
исследованиях — сразу под информером погоды. Каждая карточка ведёт на
сайт первоисточника (открывается в новой вкладке).

Сайт статический, поэтому блок **не подтягивает новости сам** — у
статических сайтов нет надёжного способа читать чужие RSS-ленты прямо
из браузера посетителя (большинство новостных сайтов блокируют такие
запросы с чужих доменов), а сторонние прокси-сервисы для обхода этого
ограничения ненадёжны для долгосрочной работы и не дают контролировать
качество и перевод текста. Поэтому — как и с товарами и паспортами —
новости вносятся вручную в отдельный файл, это лучше вписывается в уже
знакомую вам схему работы с сайтом.

**Как добавить/обновить новость (вручную — сайт статический, сам
новости не подтягивает):**

1. Найдите свежую новость на любом сайте о птицах или орнитологии —
   неважно, зарубежном или русскоязычном (сейчас в примере три новости
   с британского birdguides.com про исследования в Финляндии, миграцию
   орлов и малых лебедей).
2. Откройте `data/news.js` и своими словами напишите короткий
   заголовок и 1-2 предложения по-русски. **Не копируйте и не
   переводите текст дословно** — это чужой материал, блок на сайте
   только коротко анонсирует его своими словами и ведёт по ссылке на
   полный текст (так и авторские права не нарушаются, и читателю
   честно: за подробностями — по ссылке).
3. Впишите точную ссылку на оригинал (`url`), название источника
   (`source`) и дату (`date`).
4. Для фотографии — зайдите на **pexels.com** (или unsplash.com),
   найдите подходящую по смыслу фотографию (например того же вида
   птицы), откройте её и правой кнопкой на картинке →
   «Копировать адрес картинки». Вставьте этот адрес в поле `image`,
   а имя автора снимка (указано на странице фото у Pexels) — в поле
   `credit`, просто для приличия (по лицензии Pexels это не
   обязательно, но хорошая практика). Если оставить `image` пустым —
   вместо фото покажется нарисованная иконка (поле `icon`:
   `"finch"` / `"eagle"` / `"swan"` / по умолчанию — общий силуэт).
5. Сохраните файл — карточки на главной обновятся сами.

**Почему именно Pexels/Unsplash, а не фото прямо со страницы
новости.** Фотографии в статьях-источниках (например на birdguides.com)
обычно подписаны конкретным автором-фотографом и переданы в галерею
именно этого издания — использовать их на другом, тем более
коммерческом сайте без лицензии нельзя, даже прямой ссылкой на чужой
сервер. Pexels и Unsplash устроены иначе: **все** фотографии в их
каталоге изначально выложены по открытой лицензии (Pexels License /
Unsplash License), которая прямо разрешает свободное использование
везде, включая коммерческие сайты, без необходимости спрашивать
разрешения. Поэтому красные флажки здесь не нужны — берите с Pexels
или Unsplash любое фото, какое подходит по смыслу.

**Если фото перестанет загружаться** (например ссылка устареет или
страница на Pexels будет удалена) — сайт сам, автоматически, заменит
его на нарисованную иконку вместо сломанной картинки. Ничего чинить
руками не придётся, но вы это заметите, если зайдёте на сайт — тогда
просто подберите новое фото тем же способом.

Записей в файле может быть сколько угодно, но на главной всегда
показываются только первые 3 — свежие новости удобно просто вписывать
в начало списка.

Рендерит блок файл `js/news.js`, стили — класс `.news-grid`/`.news-card`
в `css/style.css`.
